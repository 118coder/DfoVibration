> 配套：`docs/HANDOFF.md`（总交接，先读其「⚡ 下一位 AI 快速接手卡」+ 第 66/67 条）。
> 涉及三个症状，均已定位/修复：
> ① 校对时「一次按压 → 两个槽位被填、混入 `GAMEPAD_045E_*`」→ **v24.2 修**（双通道按窗口合并）；
> ② 校对时「摇杆串键」（按下摇杆时轻轻推动 → 方向/回弹被记进去）→ **v24.3 修**（按槽位过滤 + 摇杆优先 XInput + 不干净提示重按）；
> ③ 「手柄按键快速映射」按手柄键没反应 → **v24.3 修**（改走捕获通道匹配已校对触发键）。
> 另有 v24.1 改的"新建映射默认不连发"，对应"进游戏按一下出两个动作"，仍待实机确认。

## 〇、结案结论（v24.3）

- 基线 **v24.3**（671 测试通过，0 失败，exe md5 `cd067b8eae75431e0cf12939fc7a9ad0`，9,221,632 字节）。

### 症状① 双通道各上报一次（v24.2 修）

- 捕获通道同时收到**两条**事件：原始 HID（`GenericDevice`，`GAMEPAD_<vid>_<pid>_<tag>_H…`）与
  XInput（`XInputCombo`，`GAMEPAD_045E_<按钮>`），**同一次物理按压各上报一次**
  （两侧都在"松开"时发送：`rawinput.rs:1378` / `xinput.rs:560`）。校准「一条事件 = 一步」→
  一次按压连吞两步：A 槽原始命名、B 槽 `GAMEPAD_045E_A`（用户 `Config.toml` 逐字复现）。
- 修复：`PadCaptureReconciler` 按压窗口把同一次按压的事件合并。
- 为什么连发映射区"逐条捕获"看着正常：它收到第一条就关通道（抢先，非合并），换个顺序也会落进 `045E`。

### 症状② 摇杆串键（v24.3 修，本轮核心）

- 用户实测 `Config.toml` 复现：
  - `手柄右摇杆·按下` = `GAMEPAD_045E_RS_Click+GAMEPAD_045E_RS_RS_Right`
    （按下 R3 时轻轻推动了，回弹方向被一起记进去）
  - `手柄左摇杆·左` = `GAMEPAD_045E_LS_Down`（斜推，MostSustained 帧选到了 Down）
- 根因：**一次手势会在同一次按压里产生多个输入**。时间窗口只能把"同一次按压"合起来，
  **分不开里面的多个输入** —— 所以必须看内容、按槽位类型挑。
- 稳方案（`pick_calibration_device`，`src/gui/gamepad_mapping.rs`）：
  - 窗口按通道各收候选（`PadCaptureCandidates`：raw / xinput 各一条；XInput 多帧的 id 取**并集**，别被回弹顶掉）
  - **摇杆槽位（`Stick` / `StickClick`）优先 XInput** —— 摇杆"方向 + 回弹"只有 XInput 有确定语义；
    并按槽位过滤 id：摇杆按下只留 click（`0x07`/`0x08`），方向只留对应摇杆的四个方向
    （LS `0x10..0x13` / RS `0x14..0x17`）：
    - 过滤后**恰好一个** → 记录（回弹被顺手丢掉）
    - **0 个或 >1 个**（斜推 / 缺 click）→ **提示重按，不推进步骤**
  - 非摇杆槽位：原始命名优先；只有 XInput 时要求恰好一个键，多键 → 提示重按
  - 非 XInput 手柄：退回原始命名（内容无法校验，但不卡死）
  - 窗口值 `PAD_CAPTURE_HOLD_MS = 300`（用户实测：600 反应迟纯，200 兜不住回弹）
- **可见性**（用户要求）：向导里每个已完成热点直接显示"记下的触发键简称"
  （`✓右摇杆按下=045E_RS_Click`）—— 原始 `H…/B…` 与 XInput `045E_…` 一眼区分，不用再跑去连发映射区核对；
  提示语按槽位类型区分（摇杆按下要垂直 / 方向要推直 / 普通键别碰摇杆）。
- 已知遗留：真组合键名经 `util::key_combo_parts` 会被多加一段设备前缀
  （`RS_Click+RS_Right` → `..._RS_RS_Right`）。连发映射页仍可能生成；校准已拒绝多键输入，故不会再产生。

### 症状③ 快速映射认不出已校对键（v24.3 修）

- 旧实现 `gp_newly_pressed_slot` 用 live 原始位组合比对（`trigger_matches_raw`），**只认原始命名** →
  XInput 命名的槽位（该手柄的摇杆类）永远不亮、不选中，按手柄键也没反应。
- 改为「监听态」：点「手柄按键快速映射」→ 开捕获通道；按下的手柄键经 `find_slot_by_trigger`
  按系统备注里的触发键匹配（原始命名与 XInput 命名都认）→ `select_slot_autostep`
  **直接选中槽位并开始设键盘键**。
- 生命周期：离开页面 / 取消 / 进校准 / 进校键 都会关掉监听与捕获通道（`gp_quick_listen`）。

- **回归测试**：`gui::gamepad_mapping::pad_capture_reconcile_tests` 10 条
  （窗口边界、双通道、回弹过滤、斜推拒绝、摇杆优先 XInput、命名匹配、简称）。
- **实机待验证**：重跑「一键校对手柄按键」（摇杆按下要垂直按、方向要推直）→ 看向导右侧每步简称是否干净；
  再点「手柄按键快速映射」按一个已校对的键 → 应直接跳到它的键盘键设置。
  ⚠ 现有 `Config.toml` 里已被污染的摇杆条目不会被自动清掉，重跑对应步骤即被覆盖。

### 症状②（进游戏出两个动作）的现状

- v24.1 已把新建手柄映射默认改为不连发（`turbo_enabled=false`），本轮未改动这块逻辑，仍待实机确认。
- 若症状②仍在且「一次按压两个动作」与命名无关，按本文第五节插桩取证；**不要靠猜**。
  ⚠ 注意：症状①的 bug 会污染槽位 → 后续按每个键都可能记错/串键，**先修①再验②**，否则观察结果不可信。

## 二、已确证事实（别再重复验证）

1. 手柄 = **20BC:5159**，RawInput HID 设备，按键/方向靠**原始报文位组合哈希**识别
   （与连发映射页同一编码 `GAMEPAD_<VID>_<PID>_<tag>_B...`）。
2. 历史配置曾同时存在 **`GAMEPAD_045E_*`（XInput 命名）** 与 **`20BC..._B...`（原始命名）**
   → 两套命名各中一条映射 = 双触发。**v23.0 起删除"页面自造 XInput 命名"，v23.1 清理历史条目，该路径已封死。**
3. 旧配置还出现过**无法解析的坏触发键**（如 `GAMEPAD_045E_LS_Left+GAMEPAD_045E_LS_LS_Up`）
   导致程序完全起不来 → v23.1 已改为"跳过 + 日志"，不再阻断启动。
4. **v24.0 起手柄页 = 连发映射的可视化 UI**：
   - 槽位靠**系统备注** `手柄<标签>（系统）`（例 `手柄A 键（系统）`）关联**一条普通映射**；
   - 校对 = 原始通道捕获 → `set_slot_trigger(slot, 捕获名)`（就是写一条普通映射）；
   - 高亮/自动选中 = 把该槽位映射的 `trigger_key` 与当前 `live.raw_position` 比对（`trigger_matches_raw`）；
   - 未校对的槽位不再"猜"名字（主按钮置灰）。
5. **当前用户 `Config.toml`（约 2 KB）实测内容**：
   - 顶层只有 **1 条映射**：`trigger_key = "Q"`, `target_keys = ["Q"]`, **`turbo_enabled = true`**, `note = ""`；
   - 预设：`默认`(空) / `测试`(Q→Q)；`current_preset = "测试"`；
   - `hid_baselines = []`、`device_api_preferences = {}`、`hid_slot_usages = []`；
   - **没有任何手柄映射** → **无法据此分析复现**。需要用户复现时的配置，或第五节插桩日志。
6. 全局 `interval = 5`、`event_duration = 5`（ms）→ 连发状态下"一按即补发"，几乎必然表现为两下。

## 五、插桩取证（H1 不成立时的唯一正解）

**目的**：拿到「**一次按压**」产生的**全部 InputEvent** 与**命中的映射**。一次即可定案。

**落盘方式**：参考 `src/vibration.rs::vib_log`（写 exe 同目录、append）。
建议新建 `SorahkDFO_input.log`，每行带 `[INP]` 前缀，便于最后 grep 清理。

**打点位置**

| 文件:行 | 打什么 |
|---|---|
| `src/rawinput.rs:1288` | 通用通道 `pool.dispatch(event)`：`device.to_string()` + Pressed/Released |
| `src/rawinput.rs:2062` | 语义通道 `pool.dispatch`（同上） |
| `src/xinput.rs:722 / :733` | XInput 通道 Pressed/Released |
| `src/keyboard.rs:87 / :98 / :541 / :944 / :1014` | worker 命中映射时：device + `target_action` + `turbo_enabled` + `interval` |
| `src/state.rs:2881` | `create_input_mappings`：启动时打印最终映射表（device → 动作），一眼看出某设备是否对应多条 |

**判据**

- **1 条 Pressed + 1 条映射命中，游戏里却是两个动作** → 问题在**注入/时长/连发**层 → 查 turbo（H1）。
- **一次按压出现 2 条 Pressed** → 问题在**输入层**（RawInput 抖动或组合哈希拆分）→ 查 `detect_hid_changes`、
  `hash_bit_pattern` / `generate_button_events`。
- **1 条 Pressed 但命中 2 条映射** → 配置里**重复触发键**（H3）→ `grep trigger_key`。

**交付前**：搜 `[INP]` 清理插桩（或移到明确标注的 debug 位置）。
