## 0. 一页总览

### 0.1 模块关系（文字版）

```text
main.rs（装配根，唯一豁免守卫的文件）
  AppConfig::load_or_create → dfo_player 启动修正 → AppState::new
  → keyboard/mouse 钩子、InputManager、vibration、audio_haptics、auto_inject、tray
  → BackendService::new(app_state, config, "Config.toml")   ← ★R2.14 新增的装配步
  → SorahkGui::run(backend)

┌──────────────────── src/gui（表现层）────────────────────┐
│ SorahkGui { backend: Backend, 纯 UI 会话字段 }            │
│  · 不再持有 AppConfig / AppState / UpdateManager          │
│  · temp_config: Option<AppConfig> 仅设置弹窗草稿          │
└──────┬──────────────────────────────▲────────────────────┘
   读: snapshot() / with_config      写: dispatch(UiCommand)
       (帧首 gather)                    update_config(Commit) /
   异步: take_* / poll_*               update_vibration_config /
       (UI 线程统一取)                 update_audio_config
┌──────▼──────────────────────────────┴────────────────────┐
│ BackendService（src/backend，Arc 门面 = UI 唯一后端入口）    │
│  cfg: Arc<ConfigStore>     ← 配置权威 RwLock<AppConfig>    │
│  app: Arc<AppState>        ← 运行态原子/通道（照旧共享）     │
│  update: UpdateManager     ← 检查更新所有权归位             │
│  events: RwLock<VecDeque<UiEvent>>                          │
│  领域文件: mappings / vibration / audio / capture / devices  │
└──────┬──────────────────────────────────────────────────────┘
       ▼
AppState + 引擎/输入层（vibration、audio_haptics、rawinput、xinput、
keyboard/mouse 钩子、sequence、job_presets …—— GUI 对它们全面断供）
```

`pub type Backend = Arc<BackendService>`（`backend/mod.rs`），句柄廉价 Clone。

### 0.2 三条数据流

| 流 | 方向 | 入口 | 说明 |
|---|---|---|---|
| 读（运行态） | 后端→UI | `backend.snapshot()` | 每帧一次，聚合 AppState 的 pub 原子量，微秒级 |
| 读（配置） | 后端→UI | `backend.with_config(\|c\| …)` | RwLock 短借只读，**帧首 gather 一次** |
| 写（命令） | UI→后端 | `backend.dispatch(UiCommand)` | 离散动作（开关/测试/预设/退出…），返回 `UiReply` |
| 写（配置） | UI→后端 | `backend.update_config(Commit, …)` | 五档提交；震动/音频另有 `update_vibration_config` / `update_audio_config` 单一写路径 |
| 异步事件 | 后端→UI | `take_* / poll_*`（UI 线程取） | 托盘请求/预设切换/HID 报文/捕获结果；`UiEvent` 队列已建（见 §3.3） |

### 0.3 一句话红线

**UI 的手只伸向 backend 门面；配置权威只有 ConfigStore 锁里的那一份；config.rs 字段名 = 用户 TOML 兼容契约（动它先过 ADR）；引擎热路径只读原子、禁加锁。**

## 1. ui_api 契约层（src/ui_api/mod.rs）

UI 与后端之间**唯一的类型契约**，全部 `Serialize + Deserialize`（serde-first：将来加 HTTP/SSE 传输适配器时零改契约）。

### 1.1 UiSnapshot —— 运行态快照（后端聚合，UI 只读）

六域结构，每帧由 `BackendService::snapshot()` 聚合一次。字段**全部来自 AppState 的 pub 原子量 / 后端服务**，UI 渲染只允许从这里与 `with_config` 取数据：

| 域 | 内容 | 字段来源（举例） |
|---|---|---|
| `CoreSnap` | 暂停/语言/config_epoch/线程数/注入保险统计/序列宏状态/S1S4 路线 | `app.is_paused()`、`app.config_epoch()`、`state::injection_guard_stats()`、`app.vib_legacy_client` 原子 |
| `InputSnap` | 实时手柄/XInput 位图/捕获模式 | `app.live_hid_state()`、`app.get_rawinput_capture_mode()` |
| `VibSnap` | 60 槽参数、26 项 item_lr、30 槽 rank_lr、评分细分、实时输出电平、职业算法 | `app.vibration_params[i]` 等原子数组逐个 load |
| `AudioSnap` | 频带 RMS/马达输出/白名单可观测性/校准结果 | `app.audio_hap.telemetry_*()`（Mutex 容错读，见 §5.3） |
| `UpdateSnap` | 检查更新阶段/进度 | `UpdateManager::snapshot()` 的 serde 友好镜像（原始版走 `update_snapshot_raw()`） |
| `CountsSnap` | 映射/连发/预设/白名单/宏计数 | `with_config` 里从 config 派生（`counts_snapshot()`） |

**为什么配置不进快照**（`ui_api/mod.rs` 设计约束 2）：
1. 整份 AppConfig 每帧克隆太贵，快照只承载运行态；
2. 配置读取走 `with_config` 短借，UI 想要哪个子结构就借哪个，语义更精确；
3. 快照要 serde 化，塞入 AppConfig 会把 TOML 持久化模型耦合进传输层。

**扩展快照字段的步骤**：① `ui_api` 对应 Snap 结构加字段（serde 化）→ ② `backend` 的 `snapshot()`（或 `counts_snapshot()`）填充——只许读既有 pub 原子/遥测访问器，**禁把新锁引进热路径** → ③ UI 从 `snap.xxx` 读。

### 1.2 UiEvent / UiCommand / UiReply

- `UiEvent`：后端攒着、UI 一次性取走的事件。现有 5 个变体：`ShowWindow`、`ShowAbout`、`PresetSwitch(String)`、`RawCaptured(InputDevice)`、`HidActivationData { handle, data }`。**注意现状**：该队列（`push_event`/`poll_events`）今天只有 backend 自测在用，GUI 消费异步回传仍走按通道的 `take_*`/`poll_*` 透传（见 §3.3）——新功能优先往 `UiEvent` 通道上靠。
- `UiCommand`：UI→后端离散命令。载荷**一律复用 config/state 类型**（如 `UpsertMapping { mapping: KeyMapping }`），保证「契约即持久化模型」，不另造镜像结构。无参命令有 action id 字符串（`toggle-pause`/`save`/`quit`/`test-pulse`…，沿用归档 WebUI 命名），`id()` 正向取、`from_action()` 反解——将来 HTTP `/api/action` 免费复用。
- `UiReply { ok, message }`：命令执行结果，`ok()` / `ok_with(msg)` / `err(msg)`。

**扩展命令的步骤**（细节见 §4）：
1. `UiCommand` 加变体；无参命令同步补 `id()` 与 `from_action()` 两处字符串（`ui_api` 自带测试 `command_roundtrip_and_ids` 会检查无参清单的往返）；
2. `BackendService::dispatch` 加 match 臂（复杂逻辑放领域文件再由 dispatch 调）；
3. GUI 调 `self.backend.dispatch(...)`。

### 1.3 Commit —— 提交档位（语义详解在 §2.3）

```rust
pub enum Commit { Memory, Save, SaveConfigOnly, SaveVib, Reload }
```

注意：`ui_api/mod.rs`、`backend/mod.rs`、架构守卫头注释里残留的「三档提交」是 A 阶段（只有 Save/SaveVib/Reload）的说法；B 阶段补 `Memory` 与 `SaveConfigOnly` 后已是**五档**。**以枚举定义与本文为准。**

### 2.2 配置读写 API 语义

- `with_config(f)`：只读短借。**闭包内禁止调用 Backend 的写方法或再进任何锁**（RwLock 不可重入，同线程重入 = 死锁）。推荐模式：帧首一个 `with_config` 块把需要的值收进局部变量，之后随意 dispatch。
- `update_config(Commit::Xxx, f)`：写配置 + 按档落盘/热重载，UI 写配置唯一入口。失败语义与旧 GUI 一致：**文件已按新值写出**；`reload_config` 失败（如映射非法）时运行态保持旧映射并返回 Err。
- `update_config_debounced(f)` / `update_vib_debounced(f)`：只改内存 + 分别对 Config.toml / 路线震动文件打脏标（调度线程静默 1 秒落盘）。
- `update_vibration_config(f)`：**震动滑杆单一写路径**——改 `config.vibration` → `apply_vibration_config` 全量镜像进引擎原子 → 去抖落盘。不动 `vibration_algo_id/ap`（JobVibration 职业叠加层）。
- `update_audio_config(f)`：音频同法——改 `config.audio_haptics` → `audio_hap.apply_config` 镜像 → 配置去抖。
- `update_vib_config_keep_params(f)`（vibration.rs）：镜像时**跳过 60 槽参数**——全职业预设会话期间 60 槽原子归 JobVibration 会话所有，不得被 config 里的通用参数覆盖。
- `save_all_now()`：立即写 Config.toml **+** 路线震动文件（`save_to_file` 既有语义），清两个脏标。
- `flush_all()`：退出兜底，只补写脏通道。`quit()` = `flush_all` + `app.exit()`（通知运行线程收尾，GUI 收到后关窗口）。
- `reload_runtime()`：无落盘重载——把 store 里最新值灌进运行态（`reload_and_apply`）。设置弹窗 Save 后用。

### 2.3 Commit 五档：各自什么时候用

| 档 | 落盘动作 | 典型场景（真实调用点） |
|---|---|---|
| `Memory` | 只改内存，不落盘 | `set_vib_item_lr_quiet`（原子+config 双写但不落盘）、`switch_vib_edition_explicit` 的中转步 |
| `Save` | `save_to_file` = Config.toml **+** 路线震动文件 | 顶栏开关（dark_mode/置顶/托盘）、音频白名单、hid_baselines、映射预设保存、窗口几何 |
| `SaveConfigOnly` | **只写 Config.toml，不碰震动文件** | **设置弹窗 Save 专用**（见下） |
| `SaveVib` | **只写路线震动文件**（S1→`Vibration-ACT.toml`，S4→`Vibration.toml`） | 震动预设应用、职业预设应用、`SetVibrationEnabled`、导入震动设置 |
| `Reload` | `save_all_now` + `reload_and_apply`（`reload_config` 两阶段热重载 + 重建手柄预设切换键绑定） | 映射 CRUD、连发白名单增删、语言切换、`current_preset` 变更 |

**SaveConfigOnly 为什么存在（重点）**——设置弹窗 S1/S4 路线切换时 temp 里是错配组合：

弹窗 Save 时序（`gui/settings_dialog.rs`）：① 帧首把运行时最新值**回灌**进 `temp_config` 的「弹窗不拥有的字段」（mappings/presets/vibration/vibration_presets/process_whitelist/update/audio_haptics/hid_baselines/window_rect_* 等）→ ② 比较 `edition_from != edition_to` → ③ `update_config(Commit::SaveConfigOnly, |c| *c = temp_config.clone())`。此刻权威 store 里是「**新路线标记 + 旧路线震动参数**」的错配组合——如果这里用 `Save` 档（`save_to_file`），`vibration_path_for` 会按**新**路线标记选文件，把**旧**路线的参数写进新路线的震动文件，覆盖掉新路线原有的那套参数。所以这一步绝不能连震动文件一起写。随后：`edition_from != edition_to` 时调 `switch_vibration_edition`（→ `backend.switch_vib_edition_explicit`：按旧值判断真切换、互换两份路线文件/镜像/落盘，内部自己再 reload），否则 `reload_runtime()`。切换动作**必须**在第一次 reload 之前做完——错配组合绝不能灌进运行态。

### 2.4 锁规则（背下来）

1. `with_config` 的闭包内**禁止**调用 backend 的写方法、`update_*`、`snapshot` 之外的任何会再进锁的东西——`AppConfig` 那把 RwLock 不可重入，同线程重入 = 直接死锁（`util::read_guard`/`write_guard` 只是中毒容错封装，不改变重入死锁性质）。
2. `update_config` 的闭包 `f` 在**写锁内**执行：闭包里只许改 `AppConfig` 字段，不许调任何 backend 方法。
3. `save_lock`（`RwLock<()>`）只负责串行化「调度线程落盘」与「前台提交落盘」的并发文件写，与配置读写锁分开。
4. 免死锁的固定姿势：**帧首 gather（可能多个 `with_config`，都是短借）→ 闭包返回后 → 再 dispatch/update**。震动页、音频页、预设快切、连发页全局参数卡全是这个形状。

### 2.5 保存调度线程

`BackendService::new` 里 `spawn_scheduler` 拉起看护线程 `backend-save-scheduler`（`util::spawn_supervised`，挂掉可见可重启），并把 store 与 BackendService 共享：

- 每 **250ms** tick 一次；每通道一个 `Debounce { dirty, since }`；
- 脏标打上后**静默满 1 秒**（`QUIET`）才落盘——高频滑杆拖动期间只标脏不打盘，与旧 GUI 的去抖语义一致；
- `tick()` 先查震动通道（`save_vib_now`）再查配置通道（`save_all_now`），失败只写 `vib_error` 日志不崩；
- 退出时 `flush_all()` 只补写当前脏的通道（GUI `on_exit` → `backend.quit()`）；
- GUI 侧旧的两段去抖脏标字段已废除（`gui/mod.rs` 有注释说明），**不要再在 GUI 里做去抖**。

## 3. GUI 三条纪律（配真实代码）

### 3.1 纪律一：渲染页帧首 gather/snapshot，之后随意 dispatch

帧首用一个（或几个短借的）`with_config` 把本帧需要的配置子结构收进局部变量，运行态取一次 `snapshot()`；之后整帧渲染只读局部变量，点击回调里随时发命令——绝不持读锁跨越写操作。

`src/gui/vibration_page/page.rs`（帧首）：
```rust
/* ★R2.14 帧首 gather: config 子结构 clone + 运行态快照各取一次 */
let vib = self.backend.with_config(|c| c.vibration.clone());
let legacy = self.backend.with_config(|c| c.vib_legacy_client);
let snap = self.backend.snapshot();
```

`src/gui/main_window.rs::render_preset_switch`（同型）：帧首一次 `(current_preset, presets)` collect，UI 闭包只记意图（`picked`），闭包返回后再 `apply_mapping_preset` 提交。

### 3.2 纪律二：写一律 `update_config` / `update_*_config` / `dispatch`，禁止碰 config 字段写入与原子 store

GUI 里**没有任何** `app.xxx.store()` / `config.field =` 的真实数据写路径；改配置要么走领域单一写路径，要么走命令，要么 `update_config(Commit)` 闭包改字段。

震动滑杆——统一走 `vib_slider_update`（`vibration_page/hints.rs`，job_mode 分流到 `update_vib_config_keep_params`），独立测试开关（`vibration_page/sections.rs`）：
```rust
self.backend.update_vibration_config(|v| {
    v.independent_test = ind;
});
```

音频滑杆——`audio_page.rs` 的 `audio_slider!` 宏（每条滑杆两行搞定）：
```rust
if changed {
    $self.backend.update_audio_config(|a| a.$field = v);
}
```

离散动作走命令——震动总开关（`vibration_page/page.rs`）：
```rust
self.backend.dispatch(crate::ui_api::UiCommand::SetVibrationEnabled(!vib_on));
```
（`SetVibrationEnabled` 在 backend 里 = config 写 + 全量镜像 + 立即落盘，修掉了旧版「只翻原子不落盘」的回滚隐患。）

特例：`SorahkGui.temp_config` 是设置弹窗的**草稿副本**（UI 自己的编辑状态），弹窗各分区直接改它渲染；Save 时才整份提交进权威（§2.3）。这不是绕过 backend——权威始终在 ConfigStore。

### 3.3 纪律三：异步回传只在 UI 线程统一取

后端线程**绝不直接碰 UI**；跨线程回传一律进队列，UI 在帧循环（`main_window.rs::update_ctx` 及其调用的处理器）里取走。当前真实通道：

| 回传 | 取法（UI 线程） |
|---|---|
| 托盘「显示主窗口/关于」 | 帧首 `take_show_window_request()` / `take_show_about_request()` |
| 手柄切换键（输入线程检出） | `handle_preset_switch_keys` 里 `take_pending_preset_switches()`（FIFO） |
| HID 激活请求/原始报文 | 帧首 `poll_hid_activation_requests()`；弹窗内 `try_hid_activation_data(handle)` |
| RawInput 捕获一帧 | 手柄捕获流程里 `poll_pad_capture()` |
| 键盘捕获 | `capture.rs::poll_pressed_keys()`（UI 以帧率轮询自做边缘检测） |

`UiEvent`/`poll_events()` 是为统一事件通道（和将来 HTTP/WebUI 传输层）建好的预留通道，**GUI 尚未接入**（今天只有 backend 单测在 push/poll）。新增异步回传时优先加 `UiEvent` 变体并从 `poll_events` 消费；若沿用按通道透传，也必须遵守「只在 UI 线程取」。

## 4. 如何新增一个功能（端到端示例）

目标：加一个「一键重启全部已停止线程」按钮。全程 4 步，**架构守卫一行不用改**。

**① 契约类型**（`src/ui_api/mod.rs`）：
```rust
pub enum UiCommand {
    // …既有命令…
    RestartAllThreads,   // 无参命令
}
```
并在 `id()` 加 `UiCommand::RestartAllThreads => "restart-all-threads"`，在 `from_action()` 加对应的反解臂（两处必须同步，`command_roundtrip_and_ids` 测试会抓漏）。

**② backend 方法**（`src/backend/devices.rs`，dispatch 加臂）：
```rust
UiCommand::RestartAllThreads => {
    for name in self.stopped_threads() { self.restart_thread(name); }
    UiReply::ok()
}
```
（纯转发已有 API、不涉及配置写入，不需要 Commit。若要写配置，就在领域文件里 `update_config(档位, …)`。）

**③ GUI 调用**（侧边栏胶囊处，`main_window.rs`）：
```rust
if ui.add(th.ghost_button("一键重启")).clicked() {
    self.backend.dispatch(crate::ui_api::UiCommand::RestartAllThreads);
}
```

**④ 为什么守卫测试不用改**：
- `no_gui_dep_outside_gui`：没在任何非 gui 文件引入 `crate::gui`；
- `gui_dependency_allowlist`：GUI 只引用了 `backend` 与 `ui_api`——两者本来就在清单里；没有 import 新的 crate 模块；
- `config_stays_leaf`：没碰 config.rs；
- `toml_contract_*`：没加/改/删任何 TOML 字段。

**什么时候守卫就真的要改**：
- **加 config.rs 字段**（新设置项）→ 把新键加进 `tests/architecture_tests.rs` 的 `EXPECTED_APP_KEYS`（或 VIBRATION 清单），提交信息写明「有意扩展」；改名/删字段 = 破坏用户 TOML = **先过 ADR**；
- **GUI 要消费一个新的 crate 模块** → `gui_dependency_allowlist` 的 `ALLOWED` 加名，提交信息写理由（这是有意识的决定，不是随手 import）；
- **backend 想依赖 gui** → 永远不发生（`no_gui_dep_outside_gui` 红灯就是干这个的）；表现层只能被消费，不能被依赖。

## 5. 红线与坑

1. **config.rs 字段名冻结**。`toml_contract_app_config` / `toml_contract_vibration_config` 把 serde 键集合按字典序固化成快照——TOML 字段名 = 老配置文件的兼容契约，**没有迁移机制**。加字段 = 有意扩展（更新 EXPECTED 清单 + 提交写理由）；改名/删除 = 必须先过 ADR。别「顺手规范命名」。

2. **`#[serde(skip)]` 的 `vibration` / `vibration_presets` 回灌**。这两字段（`config.rs`）读写都不经 Config.toml，唯一持久化来源是路线文件——**整份结构在内存里怎么复制，它们就怎么跟着走**。设置弹窗 Save 的回灌清单里 `temp_config.vibration = live.vibration` 与 `temp_config.vibration_presets = live.vibration_presets` 两行**必须保留**：漏掉 = 弹窗打开瞬间的旧震动参数灌回权威 store，随后任何一次 SaveVib/Save 都会把旧参数写回路线文件。

3. **引擎热路径禁 Mutex**。震动引擎满速轮询读 AppState 原子量——快照/新 API 只许 load 既有原子，**不许往热路径上加锁**。唯一例外是 `AudioTelemetry` 的 Mutex，只许 UI/快照侧用容错读（`lock().unwrap_or_else(|p| p.into_inner())`，见 `backend/audio.rs` 头注释）；`audio_telemetry()` 用 `try_lock`，拿不到返回 None，GUI 显示「本帧跳过」。

4. **GetAsyncKeyState 轮询的归属**。分两类：**捕获会话**（键位捕获弹窗轮询全键表）在 `backend/capture.rs::poll_pressed_keys`——输入传输层归后端，GUI 禁止直接碰输入层模块；**热键边缘检测**（连发切换键/预设切换键的按下沿）仍留在 `gui/main_window.rs`（`handle_keyboard_input` / `poll_switch_key_down`）——因为切换动作要「落盘 + 热重载」，只能发生在 UI 线程；手柄类切换键则由输入线程检出后经 `pending_preset_switches` 队列送回 UI 执行。新功能先想清楚属于哪类，别捕全键表也照抄进 GUI。
   顺带一坑：`backend/mod.rs::poll_pressed_keys_static` 与 `capture.rs::poll_pressed_keys` 是两份**相同**键表实现（静态版给无句柄弹窗用）——改键范围要两处同步。

5. **doc-test / MinGW 非ASCII 路径失败 = 环境坑，非代码问题**。本仓库源码目录含中文；MinGW ld 在非 ASCII 的 `CARGO_HOME`/`TMP` 下会报 `cannot find -lwindows.0.53.0`、doctest 对象文件丢失——**不代表代码坏了**。手动跑 cargo 必须带 `CARGO_HOME=/c/Users/12290/.cargo TMP=TEMP=/e/Sorahk-build/.tmp`，构建只在 `E:\Sorahk-build`（ADR-0004 第 4 条，规范 E1/E3）。本机跑测试见到这类报错先查环境变量，不要改代码。

6. **「三档提交」旧注释**。个别头注释（`ui_api/mod.rs` 顶部、`tests/architecture_tests.rs` L97）还写着「三档提交」——那是 A 阶段遗留，`Commit` 现为五档（见 §1.3）。以枚举定义为准，别按旧注释少实现两档。

7. **双文档别迷路**。本文 = R2.14 前后端分离的**架构导读**（边界/范式/坑），改前后端边界时同步本文；`docs/HANDOFF.md` = **逐版本交接流水**（4000+ 行，最新在顶，查「当时为什么这么改」的病历），交付版本时往上加节；`CONTEXT.md` = 领域词汇唯一来源，新概念先补它；`docs/开发维护规范.md` = 强制铁律；`docs/cookbook.md` = 扩展食谱（加参数/加页面/加设置项的配方）。

## 6. 架构守卫（tests/architecture_tests.rs）

这组测试不测功能对不对，测**结构契约有没有被无意识破坏**。红灯 = 先读本文件头注释，不是删断言。

| 测试 | 守什么 | 口径 |
|---|---|---|
| `no_gui_dep_outside_gui` | 表现层只能被消费，不能被依赖 | 除 `src/gui/**` 与 `src/main.rs`（装配根）外，任何文件剥掉行注释后出现 `crate::gui` 即红灯 |
| `gui_dependency_allowlist` | GUI 只许消费清单内模块 | R2.14 收紧后清单 = `gui, ui_api, backend, config, state, i18n, util, job_presets, sequence, hid_layout, audio_haptics, update`；rawinput/xinput/vibration/auto_inject/input_manager 已移出——**输入层/引擎/系统层对 GUI 全面断供**。清单内模块也只许用「契约词汇类型与纯函数」，不碰可变状态入口 |
| `config_stays_leaf` | 配置是叶子不是依赖枢纽 | config.rs 只许依赖 `i18n` + `util`；长出新依赖先过 ADR |
| `toml_contract_app_config` / `toml_contract_vibration_config` | TOML 字段名 = 用户配置兼容契约 | serde 键集合按字典序与 `EXPECTED_APP_KEYS` / `EXPECTED_VIBRATION_KEYS` 快照比对；丢键=有人删/改名字段，多键=有意扩展没进清单 |

**改清单的规矩**：更新对应 `ALLOWED` / `EXPECTED_*` 常量，并且**提交信息里写明理由**——这是「有意识的决定」，不是随手 import。依赖图是靠测试钉住的，不是靠自觉。
