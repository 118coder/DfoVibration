## 0. 这个项目是什么（30 秒）

基于 Sorahk 的 DNF 游戏工具：**连发**（键盘/鼠标/手柄触发 → 目标键重复敲击/序列宏）+
**手柄震动适配**（注入 DLL 采集战斗事件 → 共享内存 → 宿主引擎 → XInput 马达）。
Rust 单 crate + egui 0.33 GUI，单文件 exe，Windows only。用户是真实玩家，**手感即正确性**。

## 2. 架构总览（改码前先看这个）

- 完整模块地图、领域词汇、依赖方向：**`CONTEXT.md`**（单一来源，改架构必同步更新）。
- 依赖方向无环：`gui → state → config`；`vibration → state + xinput`；`main → 装配`。
- 线程模型：13+ 线程共享一把 `Arc<AppState>`（原子量为主）；GUI 与引擎的唯一耦合面 =
  60 槽原子参数 + 具名原子量。
- **职责单一原则**：改哪个域就只开那个域的文件（见 CONTEXT.md 模块地图），不要把逻辑
  跨文件铺开；一个文件超过 ~1500 行时应考虑按职责目录化（参照 C 系列拆分的模式）。

### 2.1 关键单一事实源（改这里，不要在别处另写）

| 事实 | 唯一位置 |
|------|----------|
| 震动 60 槽下标常量 (P_*) | `src/vibration/params.rs` |
| config ↔ 60 槽双向映射 | `src/vibration/params.rs`（`for_each_named_param!` 宏表 → 双向 fn；state/gui 只是委托） |
| GUI 颜色/字号/间距 token | `src/gui/theme.rs`（业务代码禁止色值字面量；`work/_palette_check.py` 校验对比度） |
| 设计规范文本 | `design.md` + `docs/DESIGN.md` |
| serde 字段（Config.toml / Vibration*.toml / JobVibration.toml） | `src/config.rs` —— **字段名与顺序是冻结契约**（ADR-0002） |

## 3. 修改流程纪律（与 vib-mod 技能一致）

1. **意图先行**：收到方向性指令先复述"你要 X，我做 A/B/C，不做 D"；多解读时列选项让用户挑。
2. **一次一事，四步闭环**：一轮只改一个变量；`patch → 构建 → 字节级验证 → 部署/截图`；
   中间不得插入其他修改；失败 = 停下修当前步，绝不在未验证产物上叠加。
3. **数据先于假设**：两侧日志对齐（DLL 探针 + 宿主 vib.log）先于任何代码修改；
   `work/analyze_hit.py` 判定器先行；最小对照实验优于机制猜测。
4. **锚点必先验证**：脚本化修改（sed/python 批量）前必须 grep 确认锚点存在且唯一；
   脚本改过的文件必须重新 Read 才能 Edit。
5. **每步独立提交**：重构/修改一个 commit 一件事，可单独 revert；提交信息写清
   改了什么 + 怎么验证的。

## 4. 代码规范

### 4.1 模块组织
- 页面/大子系统用**目录模块**：`mod.rs`（声明 + 文档 + 对外 re-export）+ 按职责的子文件。
- 每个拆分文件头部注释写明：职责一句话 + 来源（"原 xxx.rs N-M 行, 日期, 重构批次"）。
- 对外路径保持稳定的手段：mod.rs 里 `pub use 子模块::*;`（例：`gamepad_mapping::get_slot`
  拆分后路径不变，callers 零改动）。

### 4.2 可见性约定（拆分后的语义等价规则）
| 原写法（单文件时代） | 拆分后写法 | 语义 |
|---|---|---|
| `pub` / `pub(crate)` | 不变 | crate 内/外可见 |
| `pub(super)`（gui 顶层文件内） | `pub(in crate::gui)` | gui 子树内可见 |
| 私有（无修饰） | `pub(super)`（子模块内） | 与"模块子树内可见"严格等价 |
| 文件内私有 | `pub(super)`（目录模块内） | 同上 |

### 4.3 GUI 专项
- 颜色/字号/间距一律取 `Theme` 字段与 token；新增色必须先进 theme.rs 并跑 `_palette_check.py`。
- 页面函数按**卡片/分区**拆方法（参照 `vibration_page/page.rs`：主编排 + 每卡片一个方法）；
  单个渲染函数禁止超过 ~400 行。
- egui 闭包注意：闭包内对 `&mut self.xxx` 的字段级捕获与长生命周期借用会冲突；
  抽方法（整 self &mut 调用）前必须确认闭包体内没有跨语句存活的借用（vibration_page
  C1b 的教训：`let p = &self.app_state…` 存活时插入 `self.method()` 调用直接编译失败）。
- 文案：GUI 以中文为主（i18n 部分回退，见 §7 已知边界）；新增文案先问是否要走 i18n。

### 4.4 配置与兼容
- serde 字段名/顺序冻结；删除字段 = 旧 TOML 忽略即可，**禁止**改字段名（无迁移机制）。
- 持久化一律 `write_atomic`；损坏文件隔离为 `.bad` 后按默认继续，绝不让程序起不来。
- 预设/职业参数的语义变更必须更新 `docs/ACT全职业特调表_v19.md` 与
  `docs/震动系统开发规范_v20.md` 对应条目。

### 4.5 注释与文档
- 版本化注释风格：`★v24.31: <做了什么>（为什么）`——保留，这是本项目的历史考古层。
- 文件级 `//!` 头注释 = 职责声明，改职责必改头注释。
- 每次实质改动更新 `docs/HANDOFF.md`（快速接手卡 + 编号日志条目）与 `CHANGELOG.md`；
  架构/术语变更同步 `CONTEXT.md`；被否决的重构方向写 ADR（`docs/adr/`）防重复踩点。

## 5. 测试规范

- **基线**：`cargo test --profile iter --tests` 全绿（R1 时点 = 789 个；lib 354 + bin 381 + 集成 54）。
- **必须保持绿的守卫**（动了震动/配置必看）：
  - `vibration::params::mapping_tests::*`（config↔槽位往返逐字节恒等）
  - `act_variants_tests`（39 职业变体校验和，逐字节）
  - `config_roundtrip_tests`（TOML 往返）
  - `vibration_params_tests` / `route_isolation_tests`（S1/S4 隔离）
- **环境敏感测试**（需要交互式桌面会话；锁屏/无人值守会假失败，对照 HEAD 复测再定性）：
  - `sequence::tests::poller_captures_synthesized_keys_end_to_end`（真实 keybd_event 注入 'A'）
  - `stuck_key_tests`（键盘钩子类）
- **结构守卫**（R1.1 起）：`cargo test --test architecture_tests` —— 依赖方向守卫 +
  serde 契约快照（TOML 字段名冻结契约的机器看守；新增字段更新 EXPECTED 常量，改名/删除先过 ADR）。
- **扩展配方**：加功能照 `docs/cookbook.md` 六张配方走，配方里标注了会拦你的守卫测试。
- **视觉验收**：启动 exe 截图走查（`work/offscreen_capture.ps1 -ExePath <exe> -OutPng <png>`，
  离屏 PrintWindow；或 `work/capture_only.ps1 -OutPng <png>` 抓运行中窗口），
  **必须带 `SORAHK_NO_AUTO_INJECT=1`**；明暗双主题 × 四页面 + 弹窗；
  色板改动加跑 `work/_palette_check.py`。（历史脚本 `_shot_pages.ps1` 已不在 work/，交接文档旧条目按此理解）
- 测试是重构的安全网：**先有测试锁行为，再做重构**；纯搬家类重构每步跑 lib 测试，
  里程碑跑全量。

## 6. 版本、交付与上传

1. 交付构建：`bash sync_and_build.sh --release`；产物 exe md5 必须记录（字节级验证）。
2. 每个用户确认稳定的版本立即入库 `release_backup\`（命名含版本+主题+日期）。
3. 上传 = 用户口令【测试通过，上传到仓库】后才执行；流程一律
   E 盘主线 commit → 同步 D 盘 clone（`work/_sync_to_d.py`）→ 开 release/feat 分支 →
   push → GitHub REST API 建 PR → 合并 → 删分支（详见 HANDOFF 第 42 条；gh CLI 未安装）。
4. 其余时刻**绝不 push**；本地 commit 随意且鼓励。
