# SorahkDFO 震动系统开发规范 (v20)

> 日期: 2026-08-15
> 目的: 整合震动系统当前全部规范, 作为后续开发/调优的唯一参考
> 覆盖: 参数体系 / 存储 / UI / 预设 / 事件协议 / 采集状态 / 搁置事项

## 〇、架构总览

```
DfoVibration.dll (游戏内, 只读采集)
  ├─ hooks: 事件/伤害飘字/震屏/怪物死亡 (stub 0-12)
  ├─ 轮询: 评分等级/细分事件/移动/相机震屏
  └─ 共享内存环形缓冲 (Local\DfoVibrationShm, 256KB)

SorahkDFO.exe (独立控制面板)
  ├─ 读共享内存 → VibEngine (vibration.rs) → XInputSetState
  ├─ Config.toml: 连发映射 (键位/鼠标)
  └─ Vibration.toml: 震动配置 + 预设
```

## 一、参数体系规范 (0-100 统一)

**铁律: 所有强度类参数最高 100** (减少玩家理解成本, 与连发页一致)。

| 卡片 | 参数 | 范围 | 说明 |
|---|---|---|---|
| 全局总闸 | 总调整/攻击/上限/衰减/连击/节奏 | 0-100 (衰减 0-500ms) | 衰减/时长为 ms, 非百分比 |
| 伤害飘字 | 通用强度/类型强度 (DOT/特效/状态/特殊/命中/受击) | 0-100 | 默认 0=关 |
| 评分特效 | 等级强度/细分事件强度 (15 项) | **0-100** | 每项独立 + L/R 权重 |
| 评分特效 | 满幅脉冲时长 | 20-1000ms | 时长类 |
| 高级震动 | 曲线/衰减/窗口/连击/脉冲 | 各异 | CollapsingHeader 折叠 |
| 马达区 | L/R 增益 % | 0-100 | 实时输出检测 |

**L/R 权重** (-100..+100, 0=保持原样): 伤害飘字用 item_lr[26], 评分特效用 rank_lr[30]。

**L/R 补码存储规范 (v20.4, 修复负数被饱和为 0 的 bug)**:
- 负权重用**补码**存 u32: 写 `(l as i32) as u32`, 读 `load() as i32`
- **禁止** `l as u32` (f32→u32 对负数饱和为 0, 导致 -15 变 0)
- 预设源码用 `lr(-15)` 辅助函数 (`const fn lr(w: i32) -> u32 { w as u32 }`)
- 适用范围: render_item_lr / render_rank_lr / 预设应用 全部

## 二、存储规范

| 文件 | 内容 | 入口 |
|---|---|---|
| Config.toml | 连发映射/键位/通用设置 | load_or_create / save_to_file |
| Vibration.toml | 震动配置 + 预设 (enabled/参数/item_lr/rank_lr/rank_type_gain/rank_level_gain/rank_duration/预设) | load_vibration_from_file / save_vibration_to_file |

**铁律**:
- 震动页所有保存 → `save_vibration_to_file(vibration_path_for("Config.toml"))`
- 连发页保存 → `save_to_file("Config.toml")`
- 加载顺序: load_or_create → load_vibration_from_file → AppState::new

## 三、UI 布局规范 (震动页卡片顺序)

1. **震动控制中心**: 开关/测试/预设行(应用/保存当前/保存为/保存/删除/还原默认)/状态
2. **马达区 (实时输出检测)**: L/R 进度条 (放在控制中心正下方)
3. **全局总闸**: 6 项基础参数
4. **伤害飘字震动 (事件类型细分)**: 启用开关 + 通用强度 + 6 类型 (每项: 名称→滑块→说明→L/R 行)
5. **评分特效震动 (等级 + 细分事件)**: 等级强度/时长 + 15 细分事件 (每项: 名称(计数)→滑块→说明→L/R 行)
6. **高级震动调校 (精细微调)**: CollapsingHeader 折叠的详细参数

**卡片规范** (vib_section): 全宽、圆角 15、内边距 16、背景 (40,42,50)/(245,238,252)、标题 16px 紫色。

**伤害飘字 / 评分特效 两卡片必须样式统一** (2026-08-15 已对齐):
- 主标题: 统一用 vib_section (16px 紫色)
- 卡片顶部说明: 11px weak
- 类型区子标题: 12px 彩色 (暗 (200,180,255) / 亮 (140,90,200)), 如 "飘字类型强度"/"细分事件独立强度"
- **每项布局顺序 (必须一致)**: ① 名称标签 (13px 深灰, 独立 label 在数值上方) → ② 数值滑块 → ③ 说明 hint (11px weak) → ④ L/R 行
  - 禁止把名称做成滑块 text (已修正: 评分特效原用 Slider.text(label), 现改为独立标签)
- L/R 马达样式: 统一 render_item_lr 风格 (L 橙/R 红滑块 + 40px 实时输出 ProgressBar + 数值)
  - 伤害飘字用 vibration_item_out 实时输出
  - 评分特效用 vibration_rank_out (新增, 30 项, 引擎输出时按 rank_out_idx 记录)

## 四、预设体系 (6 个内置预设)

| 预设 | 设计理念 | 关键参数 |
|---|---|---|
| 默认 (均衡全能) | 清爽脆快, 偏轻 | 上限 45, 衰减 50ms, 命中 40/特殊 55 |
| 高振幅 (重型打击感) | 刀刀到肉, 长余韵 | 上限 70, 衰减 75ms, 命中 85/特殊 100, 曲线 180 |
| 节奏律动 (技能节奏感) | 极短脆, 节拍感 | 衰减 35ms, 特效周期 80ms, 右马达强 |
| 极简轻巧 (刷图省电) | 最低存在感 | 总闸 80, 上限 45, 命中 35 |
| 实战竞技 (高难预警) | 生存预警最大化 | 受击 90/状态 70, 静默 250ms, 反击 200% |
| 测试版(全0) | 玩家自行设计 | 全 0 |

**预设结构**: `{ name, params[60], item_lr[26], rank_lr[30], rank_type_gain[15], rank_level_gain, rank_duration }`

**铁律**:
- 新增预设参数 → 必须同步: 结构体 + serde helper + save_vibration/load_vibration + 应用/保存当前/新建/还原默认 4 处逻辑
- 应用预设时**内置同名预设优先** (兼容旧 Config/Vibration.toml 缺字段)
- 评分参数 ≤100

**预设评分参数调优 (v20.1)**:
| 预设 | 等级 | 时长 | 移动强度 | 细分特点 | rank_lr (评分 L/R) |
|---|---|---|---|---|---|
| 默认 | 100 | 300 | 45 | 全 70-100 | 移动 L-15/R+10, 暴击特写 L+10 |
| 高振幅 | 100 | 450 | 40 | 重击类 100 | 暴击 L+20/R-10, 最终击杀 L+25, 暴击特写 L+30/R-15, 怪物死亡 L+20, 移动 L-25 |
| 节奏律动 | 100 | 200 | 50 | 全 80-90 | 评分点/暴击/释放技能 R+15~20, 暴击特写 R+30 |
| 极简轻巧 | 60 | 180 | 35 | 全 40-50 | 全轻微 R+5, 移动 L-25 |
| 实战竞技 | 100 | 380 | 50 | 闪避/怪物死亡 100 | 闪避 L+30, 怪物死亡 L+30, 暴击特写 L+20, 移动 L-20 |

**组合调优原则 (v20.1, 调参时必须整体考虑)**:
- 移动必须轻 (不抢主震动): 引擎整体系数 0.55 + 预设移动强度 35-50 + 移动 rank_lr 偏弱 (L-20~25)
- 重击感 = L 马达强 + 长时长 + 高曲线 (高振幅)
- 节奏感 = R 马达强 + 短时长 + 特效周期 (节奏律动)
- 生存预警 = L 马达强 + 高细分强度 (实战竞技闪避/怪物死亡)

**移动走路质感 v2 (vibration.rs, 2026-08-15)**:
- 步频 ~380ms (自然步频), 着地(前 25%)柔和脉冲 0.5, 抬脚(后 75%)极轻 0.1
- 整体系数 0.55: 移动音量低, 只做"存在感"不做"震感"
- 相位交替: 左脚步 L 主 / 右脚步 R 主 (走路韵律, 次马达 0.4)

**移动走路质感参数化 (v20.3, 已进高级震动调校区 A2)**:
- params[23] 移动步频 ms (默认 380, 范围 200-800)
- params[24] 移动着地脉冲 % (默认 35, 范围 10-100)
- params[25] 移动抬脚保持 % (默认 8, 范围 5-50)
- params[26] 移动整体增益 % (默认 40, 范围 10-100)
- params[27] 移动平滑系数 % (默认 30, 范围 5-100) — 输出平滑插值, 消除马达嗡嗡声
- params[28] 移动最低输出阈值 % (默认 4, 范围 0-20) — 低于阈值输出归 0, 消除马达沙沙声
- 引擎读取这些参数替代硬编码; 预设 params 23-28 各预设独立

**移动走路质感 v3 (vibration.rs, 消除嗡嗡/沙沙声)**:
- 正弦步伐: 每步平滑起伏 (0→峰值→0, 无方波突变)
- 平滑插值: move_out_l/r 每帧向目标过渡 (平滑系数), 步伐交替不突跳
- 低强度抑制: 输出低于阈值归 0 (避免低强度马达电流声/沙沙声)
- 相位交替: 左脚步 L 主 / 右脚步 R 主 (次马达 0.4)
- 平面 XY 移动 (DNF) 无需精细地形, 简洁轻柔步伐即可

**严格设计规范 (v20.2, 用户要求)**:
1. **修改任何参数, 必须同步 UI 显示** — 内置默认预设的 params/item_lr/rank_lr/rank_type_gain/rank_level_gain/rank_duration
   在启动时**始终应用** (main_window.rs INIT_DONE 逻辑), 保证 UI 显示最新设计值
2. **新增算法必须进高级震动调校区** — 任何新增引擎算法/可调系数, 必须在高级震动调校
   CollapsingHeader 内加对应滑块 (如 A2 移动走路质感)
3. **禁止硬编码可调参数** — 引擎算法系数一律参数化 (params[60] 槽位), 不许写死在代码里

## 七、开发注意事项

1. **评分参数必须 ≤100** (0-100 统一)
2. **震动保存走 Vibration.toml**, 连发走 Config.toml
3. **预设 4 处逻辑同步** (应用/保存当前/新建/还原默认)
4. **DLL 改动后**: build.bat 编译 → 复制到 us_extend_dll\DfoVibration.dll (先停游戏)
5. **Rust 改动后**: cargo build --release → 停止 SorahkDFO → 复制 sorahk.exe → SorahkDFO.exe
6. **IDB 库**: 主库 DFO.exe.i64 (用户恢复), 备用 work\DFO_scan.i64; 勿用 -c 重建主库
7. **debug DLL**: gcc -DVIB_DEBUG_TXT 构建 (日志刷屏, 用完换回 release)
8. **避免直接调用游戏函数** (曾崩溃): 用只读内存 + 模拟算法
9. **时间比较守卫 (v14.1 定稿)**: 凡 `before(now, deadline)` 类比较, deadline 的
   0/未初始化哨兵**必须**先做 `!= 0` 守卫 —— GetTickCount 跨 2^31 (开机 24.8 天) 后
   `0.wrapping_sub(now) as i32` 翻正, 0 哨兵会被读成"未来 21 亿 ms"
   (实锤事故: silence_until=0 导致开机超 24.8 天后普通攻击全静默)。
   新增任何时间戳状态字段时, 同时写"哨兵如何表示未设置"的注释。

## 九、高级算法新增纪律 (2026-09-09 用户定稿, 强制)

> 背景: 群怪聚合算法 (v14.1) 首版把参数做成了引擎内置常量, 用户实测后明确要求:
> **今后凡新增高级算法或调整算法行为, 相关参数必须同步加入玩家可调参数 (GUI 滑块/开关),
> 让玩家自由调控。违反此条 = 返工。**

1. **GUI 可调是硬要求**: 每个新算法的行为参数必须有对应滑块/开关, 且提供
   **明确的关闭路径** (0 = 关闭/回到旧行为)。不允许"内置常量不可调"。
2. **参数走独立 config 字段链路** (仿 throttle 先例, 不占 60 槽位数组):
   `config.vibration.xxx` (serde default) → `AppState.vibration_xxx` 原子
   → run 循环每帧同步进引擎字段 → 引擎按字段生效。落盘走 Vibration.toml
   (纯 serde, 无手工模板)。
3. **默认值 = 关闭或旧行为**, 除非用户明确要求默认开启; 开启不得影响
   S4+ 新方案路径 (gate 在 legacy 或算法开关之后)。
4. **回归测试双态必备**: ①关闭态 = 与旧行为逐字节一致; ②开启态 = 预期新行为。
   引擎侧行为差异必须有 vib.log 诊断行可核对 (如 [CARRY]/[FLUSH])。
5. **同步文档**: HANDOFF 记录参数链路与滑块位置; 本规范追加算法说明;
   若参数语义与 60 槽位预设相关, 注明与预设参数表的关系。

## 十、命中风暴抽样 v16 (2026-09-10 上线)

> 用户定稿算法 (原话): "角色在极短的时间内命中事件暴增 (受伤类排除在外) 则只会读
> 一部分的震动; 在角色在极短的时间内暂停命中时间后恢复刀刀震动。"

- **语义**: 统计窗 `storm_win_ms` (默认 1000ms) 内**纯命中事件** (0x01) 数量;
  达到 `storm_thr` (默认 10) → 进入风暴, 确定性抽样保留 `storm_keep_pct`%
  (默认 50, 即每 2 条震 1 条); 距上一条纯命中超过 `storm_pause_ms` (默认 400ms)
  → 立即退出风暴, 恢复刀刀震动。
- **排除项 (硬约束)**: 受击 0x02 (受伤类)、DOT 0x20、状态 0x08、特效 0x04、
  特殊攻击 0x10 全部不计数、不丢弃 —— 风暴只作用于"你打出去的普通命中"。
- **丢弃语义**: 被抽样丢弃的事件整条跳过, **不打 IVL 锚点 / 不进聚合记账 /
  不占命中限频名额**。与 merge_keep/hitcap 的"超额记账不丢击"互补: 风暴期宁可
  少震, 不要记账-补发形成的节拍堆叠 (狂战士双倍打击+群怪的实测定性)。
- **生效范围**: 仅 S1 老方案 (`self.legacy`), S4+ 路径逐字节不变 (红线)。
- **参数链**: `config.vibration.storm_thr/storm_keep_pct/storm_win_ms/storm_pause_ms`
  (serde default 10/50/1000/400) → AppState 四原子 → run 循环同步 → 引擎。
- **GUI**: 震动页「群怪不打手」卡 → "命中风暴抽样"小节 (四个滑块, 阈值 0=关闭)。
- **诊断**: vib.log `[STORM] 命中风暴开启 (窗Nms 内 M 条)` / `[STORM] 停顿恢复 -> 刀刀震`。
- **默认开启的例外依据**: §9.3 允许"用户明确要求默认开启" —— 本算法即用户为
  狂战士"疯狂震"问题点名要求; 关闭路径 = storm_thr 调 0。
- **与 60 槽预设的关系**: 四个参数为独立 config 字段 (不占槽位), 预设切换不影响;
  预设的命中/特殊/受击强度与密度/连击压制参数仍按原链路生效, 风暴是叠加的
  最后一道"暴增抽样"闸。

### 十·补 · 风暴期静音怪物异常反馈 v16.6 (2026-09-10, 可选开关)

- **语义**: 勾选后, 命中风暴期间 (storm_active 且距上一条纯命中未超 storm_pause_ms)
  0x04 怪物出血/中毒跳字**零痕迹丢弃**: 不注入、不打注入窗戳、不计密度、不进聚合记账。
  风暴结束 (时间窗判定, 停手超过 storm_pause_ms 即恢复, 无需等下一发命中) 自动恢复。
- **边界**: 仅 S1; 仅纯 0x04 (玩家 DOT 0x20 / 状态 0x08 / 特殊 0x10 不受影响);

## 十一、统合衰减期 v17 (2026-09-10, 用户定稿)

> 用户概念: "在大量命中之后的震动, 进行归一化衰减处理, 保证即使是不停地连续命中,
> 都会有一个固定的衰减事件让其瞬间消失。每一个命中事件都因为产生新的, 旧的消亡,
> 新的继续震, 而造成持续震动的效果。"

- **语义** (仅 S1, 仅普通命中通道 ch=3, 仅在风暴期; 默认关):
  风暴期每次命中到达注入点时: ①旧包络**瞬间清零** (left/right/decay 置 0, 不叠加
  不拖尾) → ②以本次强度重新起振 → ③衰减时间统一固定为 `storm_unified_ms`
  (不再用各事件衰减 p35 与 item_lr[3] 权重) → ④到点 (`unified_until`) 由 tick
  **硬归零**, 旧震动瞬间消失。
- **让路规则**: 开启时该通道绕过 (a) 风暴抽样 (每一击都重新起振)、
  (b) 注入间隔门 IVL、(c) 命中限频与聚合记账 (不记账不变厚)、
  (d) Burst 保底地板 (否则硬归零后右马达会被地板立刻抬起, 实测 left=0/right=1.0)。
- **哨兵**: `unified_until=0` = 未布防 (规范 §7.9 守卫纪律)。
- **参数链**: `config.vibration.storm_unified_enabled` (bool, default false) +
  `storm_unified_ms` (u32, default 120, GUI 40-400) → AppState 原子 → run 同步 → 引擎。
- **GUI**: 「群怪不打手」→ 命中风暴抽样小节: 复选框 + "统合衰减期 ms" 滑块。
- **测试**: 重触发+抽样让路 / 到点硬归零+哨兵清零 / 关闭态抽样照旧 / 新方案红线。

### 十·补 · v18 预设取值规则 (2026-09-10, 用户定稿)

> 用户要求: "假设用户不保存并覆盖同名预设参数的话, 点击应用的时候回到保存的时候。
