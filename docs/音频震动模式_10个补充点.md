# 音频震动模式 —— 你还没想到的 10 个点

> 日期: 2026-11-09 · 状态: v24.50 实现后补充池 (按建议实施顺序排序)
> 主文档: `docs/音频震动模式策划案.md` (P0/P1 规格) · `docs/音频震动模式调研.md` (技术依据)
> 标注: ★已随 v24.50 实装 / 建议进入下个迭代 / 远期

---

## 1. 音量归一化 (AGC) —— 参数不因游戏音量而失效 ★高优先

**问题**: 用户把游戏音量调到 30%, 音频引擎收到的能量整体缩到 1/10 → 默认参数全线失灵
(该震的不震), 用户只会觉得"这功能不行", 不会想到是音量问题。这是**最可能的差评来源**。

**方案**: 两级——
- 会话校准: 引擎启动/切游戏后监听 5s, 把能量分布的第 90 百分位归一到目标电平 (乘法系数, 上限 +12dB 防止静音场景疯狂放大噪声);
- 慢速 AGC: 每帧系数向目标缓慢靠拢 (时间常数 ~5s), 枪声瞬态不被"补偿掉"。

**成本**: 引擎内 ~50 行 + 1 个校准状态机。UI 加一个"音量自适应"开关 (默认开)。

---

## 2. 马达占空比/热保护 ★已随 v24.50 实装

音频是**连续**驱动 (不同于 DLL 离散事件), 转子马达长时间满幅有发热/退磁风险。
v24.50 已实装: 双马达任一 >85% 持续 10s → 自动限幅 60% 持续 5s (引擎内, vib.log 记录)。
后续可加"手感档位"(温柔/标准/狂暴) 改变 DUTY_HIGH/DUTY_CAP 参数。

---

## 3. 按进程环回 —— 只听游戏, 不听微信语音 ★P1 首位

**现状 (v24.50)**: P0 用"默认输出设备全量"——系统里所有声音都进分析器。看视频时弹微信语音,
震动会跟着乱。

**方案**: wasapi 0.27 的 `AudioClient::new_application_loopback_client(pid, include_tree)`
(调研报告 §4.2 已核实)——按 PID 精确采集, 飞智"只读游戏进程音频"同款。配合现有白名单:
前台游戏在白名单 → 拿 PID 开进程环回。

**注意**: 进程环回要求 Win10 2004+ (19041); 旧系统自动回退全量环回 + UI 提示。

---

## 4. 一键延迟自测 —— 不用手机 240fps 数帧

**问题**: 策划案 §7.1 的端到端延迟验收要手机慢动作录像, 普通用户做不了。

**方案**: 页面加【延迟自测】按钮: WASAPI render 播一记 5ms click → 同一环回立即收到 →
两点时间戳差 = 系统音频链路延迟 (10-30ms 固定项) + 已知的软件分析延迟, 合计显示
"预计枪响→起震 ≈ N ms"。把"玄学手感"变成一个数字。

**成本**: ~80 行 (render 端一次性开流)。

---

## 5. 技能音效指纹 —— DNF 玩家的"这个声音震一下" (差异化卖点)

**思路**: YAMNet 只认识"枪声/爆炸"这种通用类, 不认识"念气波/觉醒"。但 YAMNet 附带
1024 维 embedding (audiomagic 导出已暴露 output_1)——

**方案**: 用户点【录制指纹】→ 采集 1s 音效 → 存 embedding 模板 → 运行时当前窗 embedding
与模板余弦相似度 >0.8 → 触发用户自定义震感。零训练、零新模型, **每个用户自建自己的
技能映射表** (飞智没有的能力, bHaptics Profile 的本地化)。

**成本**: embedding 提取已有; 模板存储 JSON; 相似度计算 ~30 行。P1.5。

---

## 6. 手感包分享 (haptics profile JSON)

把"音频参数 + 语义映射表 + (未来的) 技能指纹"导出成一个 `手感包.json`,
导入即用。社区可流传 "DNF 手感包 / CS2 手感包 / 只狼手感包"。
基建: 连发页已有导入/导出先例可抄; 红线: 导入文件必须过 serde 校验 + 数值 clamp (防坏文件)。

---

## 7. 低电量与性能档

- **手柄电量**: XInput 无标准电量 API, 但可用"蓝牙手柄断连前异常"规避——更实际的方案是
  设置里加"省电上限 %"(如 60%), 低电时用户自己切;
- **性能档**: 笔记本电池供电 → 自动降档 (FFT 1024→2048 hop 减半采样 + 语义层暂停),
  CPU 从 ~5-10% 单核 降到 ~2%。检测: `GetSystemPowerStatus`。

---

## 8. 多手柄差异化路由

现状: `send_vibration` 扫 0..4 槽写**第一个**已连接手柄 (全项目单手柄语义)。
音频模式解锁一个新场景: 双开/双人时——
- 1P 手柄吃 DLL 事件, 2P 手柄吃音频事件;
- 或"主播手柄震, 观战手柄不震"。
需要 send_vibration 支持按槽位路由 (现有 60 槽/写入去重都是按槽的, 改动面可控)。远期。

---

## 9. 听觉隐私红线 —— 识别日志只写标签, 不写内容

环回读到的是**系统全部声音** (含语音通话)。红线:
- 语义层日志**只允许**写类目标签 ("Gunshot 87%"), 绝不写任何音频内容/转写;
- 不做也不引入语音转文字;
- 白名单模式 (点 3) 天然缩小旁听面;
- 文档明示"本功能只监听, 不录音、不上传" (YAMNet 本地推理, 无网络)。

这是分发版必须写进使用说明的一条。

---

## 10. 模型 mod 框架化 —— 未来零代码换更强模型

YAMNet 的 AudioSet mAP 只有 0.306, EfficientAT mn04 有 0.471 (调研报告 §3.3) 但没有
官方 ONNX。把 `models/` 升级成 mod 框架:

```
models/
  yamnet.onnx                    # 内置默认
  mymodel.onnx + manifest.json   # {"name":..., "input":"waveform f32 [n] @16k",
                                 #  "labels":"mymodel_labels.csv", "sha256":...}
```

加载器按 manifest 适配输入规格/标签表, sha256 防坏文件。用户社区可以自己转换并分发
更强模型, 宿主零改动。(本次已做的双轨: 个人版内嵌 / mod 目录加载, 是这个框架的第一步。)
