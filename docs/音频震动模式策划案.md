## 1. 这是什么, 给谁用

### 1.1 产品定位

在现有震动体系里**新增一路事件源**: 现在的震动全部来自注入 DLL 抓到的游戏内部事件;
音频模式改为**监听系统声音**, 用信号分析 + AI 识别把声音翻译成震动。

三种使用场景:

| 场景 | 用户 | 价值 |
|---|---|---|
| **DFO 免注入震动** | 不想用/不能用注入 DLL 的玩家 (客户端更新导致 DLL 失配的空窗期) | DLL 失配时震动功能不停摆 |
| **通用游戏震动** | FPS/动作类任意游戏 | 借用飞智式体验, 无需逐游戏适配 |
| **媒体强化** | 听歌/看视频想加触感 (参考 xbox-audio-rumble-studio 的用法) | 顺手赠品, P2 再宣传 |

### 1.2 与现有模式的关系 (定位图)

```
震动输出 (唯一出口 send_vibration, 60槽治理, 写入去重)
   ↑                      ↑
DLL事件(现有,S1/S4)   音频事件(新增,VEV_AUDIO_*)
   ↑                      ↑
共享内存 ring          WASAPI环回 → DSP快通道 + YAMNet慢通道
```

- **默认互斥**: 同一时刻只允许一路事件源生效 (GUI 单选)。P2 再考虑混合。
- 音频模式**尊重**现有全局语义: 暂停键 (切换键)、前台进程白名单 —— 游戏不在白名单,
  音频引擎自动闲置 (与飞智"只读指定游戏进程音频"同语义, 用 `wasapi::record_application`
  按 PID 精确采集)。

## 2. 核心概念 (用户视角, 写进 UI 文案的原话)

| 概念 | UI 文案用的大白话 | 技术对应 |
|---|---|---|
| 耳朵 | 「游戏出声的同时, 我们抄一份声音来分析 (不影响游戏正常发声)」 | WASAPI loopback |
| 条件反射 | 「刚发生一记突然的响声 → 立刻震」(20-40ms) | 谱通量 onset + 频带能量 |
| 翻译官 | 「AI 听出这是什么声音: 枪声/爆炸/音乐/说话」(约 0.5-1 秒) | YAMNet, 521 类 |
| 纯净反馈 | 「BGM 和人声不触发震动」 | Music/Speech 置信度门控 |

预期管理 (写进帮助文档, 防止拿飞智 6 Pro 对比):
> 飞智 6 Pro 用 4 颗音圈马达 (可震任意频率), Xbox 手柄是 2 颗转子马达 (只有低频+高频两路)。
> "枪响手震、爆炸猛震、放歌不乱震"这些核心体验一致; 马达震动的"细腻层次"受物理限制,
> 不是本工具算法问题。

## 3. P0 功能规格: 快通道 (无 AI, 先玩起来)

### 3.1 音源 (Audio Source)

| 项 | 规格 |
|---|---|
| 采集方式 | WASAPI loopback, 共享模式, 10ms period, 默认输出设备 |
| 按进程采集 | P0 先做"默认输出设备全量"; 按进程 (record_application) P1 补上 |
| 采样率 | 设备原始率采集 (通常 48kHz), 分析前重采样统一 48kHz |
| 声道 | 立体声保留 (L/R 空间路由用), 分析时可混单声道 |
| 设备热插拔 | 拔掉输出设备 → 引擎静默并每 5s 重试枚举; 恢复后自动续上, 不崩溃不残留马达输出 |
| 静音检测 | 环回连续 3s 无新数据 (平台特性: 无播放时 ring 不推进) → 马达归零 + 状态显示「等待声音」 |

### 3.2 分析引擎 (DSP)

| 项 | 规格 | 依据 |
|---|---|---|
| 分帧 | 1024 样本窗 / 512 hop @48kHz (≈21ms/帧, 46 帧/秒) | librosa onset 标准配置 |
| 频谱 | rustfft 实数 FFT, 幅度谱 | rustfft 6.4.1, MIT |
| 频带 | 5 带: 超低 20-80 / 低 80-250 / 中 250-2k / 高 2k-8k / 超高 8k+ Hz, 各带 RMS | 飞智公开链路同构 |
| onset | 谱通量 (半波整流差分) + **自适应阈值 = 滑动中位数 + k·MAD** (k 默认 3, 可调) | Dixon 2006 (DAFx); librosa onset |
| onset 节流 | 同一 80ms 窗内最多触发 1 次; 每秒上限 12 次 (DNF 技能连放保护, 上限可调) | DNF 密集音效特化 |
| 包络 | onset: attack 0ms / release 默认 120ms; 持续能量: attack 80ms / release 300ms | 连打不粘手 |
| 空间路由 | L/R 声道 RMS 各自驱动同侧马达权重 (左右声道差 → 左右马达差) | 飞智"声道路由" |

### 3.3 默认映射表 (P0, 频带规则, 全部可调)

| 触发条件 | L 马达 (低频) | R 马达 (高频) | 语义 |
|---|---|---|---|
| onset 且 低+超低占比 ≥ 50% | 90% 脉冲 120ms | 40% 短脉冲 | 爆炸/重砸 |
| onset 且 中+高占比 ≥ 60% | 30% 脉冲 | 85% 脉冲 60ms | 枪声/打击 |
| onset 其他 | 60% | 70% | 通用响声 |
| 持续低频 >300ms (无 onset) | 30-60% 跟随包络 | 10% | 引擎/环境低鸣 |
| 无 onset 且总能量 < 静音阈值 | 0 | 0 | 静默 |

最终数值**以实机调参为准**, 本表是首发默认值。

### 3.4 参数面板 (P0, 全部带默认值 + 提示文案)

| 参数 | 范围 | 默认 | 说明文案 |
|---|---|---|---|
| 总开关 | 开/关 | 关 | 「用游戏声音自动驱动震动 (免注入, 任何游戏)」 |
| 音源 | 默认输出/按进程 | 默认输出 | P1 起可选按进程 |
| 总强度 | 0-200% | 100% | 全局缩放 |
| 低频增益 | 0-200% | 100% | 爆炸/重击的沉闷感 |
| 高频增益 | 0-200% | 80% | 枪声/打击的脆响 (默认略压, DNF 打击音中高频偏多) |
| onset 灵敏度 | 1-8 (阈值倍数) | 3 | 越小越容易触发; 太小会把 BGM 鼓点当枪声 |
| 冲击衰减 | 50-500ms | 120ms | 一下响声震多久; 太长连打会粘成一坨 |
| 持续音强度 | 0-100% | 40% | 引擎/环境低鸣的跟震 |
| 静音阈值 | 0-100 | 20 | 比这更小的声音不震 |
| 每秒触发上限 | 4-30 | 12 | DNF 连放技能保护 |

### 3.5 可视化 (调参时看得见, 是好手感的一半)

- 实时频谱条 (5 频带, 每帧刷新)
- L/R 马达电平条 (与真实输出同步)
- onset 闪点 (触发的帧在频谱上打高亮)
- 这套用 egui 直方图自绘, 不引第三方绘图库 (守架构依赖方向)

### 3.6 边界行为

| 情况 | 行为 |
|---|---|
| 暂停 (切换键) | 音频引擎冻结, 马达归零; 恢复自动继续 |
| 前台不在白名单 | 引擎闲置 (同现有语义), 状态显示「等待白名单游戏」 |
| 与 DLL 模式 | 互斥单选; 切换时先归零马达 200ms 防叠加 |
| 手柄未连接 | 引擎照常分析, 输出空转 (与现有 send_vibration 行为一致) |
| 配置 | 写入 `Vibration.toml` 新节 `[audio_haptics]` (P0 就建节, 字段逐步加; serde default 兼容) |

## 4. P1 功能规格: 语义层 (YAMNet)

### 4.1 模型与分发

| 项 | 规格 |
|---|---|
| 模型 | yamnet.onnx (~15MB, 521 类, Apache-2.0, 来源 audiomagic/yamnet-onnx) |
| 推理 | ort 2.0.0-rc.15, 构建期静态链接 ONNX Runtime (单 exe 免 DLL) |
| 输入 | 16kHz 单声道 0.96s 窗 / 0.48s hop (自 48k 重采样) |
| CPU | 每帧 69.2M 乘加, 约 5-10% 单核 |
| **分发 (待拍板 D1)** | 方案甲: 内嵌 exe (体积 +15MB, 离线可用); 方案乙: 首启弹窗下载到 `%APPDATA%\SorahkDFO\models\` (exe 不膨胀, 断网降级 P0) |
| 降级 | 模型缺失/加载失败 → 自动退回 P0 纯 DSP, 状态栏提示 |

### 4.2 纯净反馈 (门控)

| 信号 | 行为 |
|---|---|
| Music 类标签置信度 > 60% | 快通道增益 ×门控系数 (默认 0.2; 可选「完全过滤 / 跟节奏 / 不过滤」三档) |
| Speech 类标签置信度 > 60% | 快通道增益 ×门控系数 (默认 0.3) |
| 关闭纯净反馈 | 门控旁路 (等效飞智关闭该选项) |

「跟节奏」档 = 把 Music 门控变成"音乐节奏跟随模式" (onset 直通, 强度随低频) —— 听歌玩法,
P2 再做, 先预留开关位。

### 4.3 语义映射表 (内置默认, 初版)

| YAMNet 标签 (AudioSet 类名) | 震感预设 |
|---|---|
| Gunshot / Gunfire / Machine gun | 重枪: R 85% 60ms + L 30% |
| Explosion / Fireworks | 重爆: L 90% 150ms |
| Engine / Vehicle | 低鸣跟随 |
| Bolt/gun shot 之外的短促打击类 (Thump/Thud/Hit) | 中击: L/R 各 60% 80ms |
| Music (全部 music 族) | 门控信号 |
| Speech | 门控信号 |

- 映射编辑器 (P1 后半): 标签多选 → (L%, R%, 时长, 重复次数) 四元组, 支持增删。
- 事件流 UI: 实时显示 top3 标签 + 置信度条 —— 用户照着识别结果配映射, 不用猜。

## 5. P2 打磨 (方向性, 不承诺)

1. **逐游戏预设**: 按前台进程自动切换音频参数 (连发页已有预设切换基建可复用)。
2. **混合模式**: DLL 事件优先 + 音频补环境层 (受击精确, 环境氛围靠听)。
3. **一键自动调参**: 听 10 秒游戏声 → 统计 onset 密度/频带占比 → 自动出参数
   (飞智没有的自定义学习, 是差异化点)。
4. **听歌模式**: 节奏跟随 + 频带可视化。
5. **60 槽正式扩容**: 音频专属参数进 params.rs 宏表 (走 cookbook 配方 1, 注意
   act_variants 校验和同步)。

## 7. 验收标准与实测方法

### 7.1 延迟 (P0 核心验收)

- **软件链路**: onset 检测处与 `send_vibration` 处各打一行微秒时间戳日志 (vib.log),
  两点差 = 软件延迟; 目标 **≤25ms** (P99)。
- **端到端**: 手机慢动作录像 (240fps) 同框拍「游戏画面枪口火光 + 手柄上轻放的牙签」,
  数帧差; 目标 **≤12 帧 (50ms)**。
- 马达物理起振 (10-30ms) 为固定项, 不计入软件优化范围。

### 7.2 资源

- CPU: 音频线程 <5% 单核 (P0) / <10% (P1 含 YAMNet)
- 内存: <50MB (P0) / <80MB (P1 含模型)
- 不开音频模式时, 现有各页行为与 v24.49 **逐字节一致** (回归测试守卫)

### 7.3 稳定性

- 音频设备拔插 ×10 循环: 不崩溃、马达不残留、自动恢复
- 1 小时 DNF 实机: 无马达卡满、无内存增长异常 (vib.log 采样通道观察)
- 暂停/恢复 ×50: 状态正确, 无"暂停后震个不停"

### 7.4 实机手感清单 (用户执行)

1. 枪响手震是否跟手 (对比不开音频模式的 DLL 受击震感)
2. 放 BGM 时是否误触发严重 (P0 预期会, 记录严重度, P1 验证门控效果)
3. 灵敏度/衰减默认值在 DNF 刷图下是否需要调
4. 1 小时长玩 CPU/发热

## 8. 风险与预案

| 风险 | 等级 | 预案 |
|---|---|---|
| BGM 误触发 (P0 无语义) | 高 | 默认参数偏保守; UI 明示 P1 纯净反馈在路; 映射表留门控开关位 |
| 用户预期差 (转子 vs 音圈) | 高 | §2 预期管理文案 + 首页提示; 不与飞智 6 Pro 直接对标宣传 |
| ort RC 版构建/兼容 | 中 | P0 完全不依赖 ort; P1 引入时先做 15 分钟 spike 实测 yamnet.onnx |
| 模型 15MB 分发 | 中 | D1 决策点 (§10); 两方案都有降级路径 |
| DNF 音效密度 | 中 | onset 节流 + 每秒上限 + 60 槽既有治理三层保险 |
| WASAPI 无播放不推进 | 低 | 静默检测 + 状态提示 (§3.1), 游戏场景实际必出声 |
| wasapi crate MSRV 1.85 | 低 | rust-toolchain 已钉 1.96.0, 满足 |

## 10. 决策点 (✅ 2026-11-09 用户拍板并实施)

| # | 决策 | 用户拍板 | 落地方式 |
|---|---|---|---|
| **D1** | 模型分发 | **双轨**: 15MB 模型作为可选下载 mod; 个人版内嵌 exe ("15MB 不算什么") | build.rs 检测 `models/yamnet.onnx` → include_bytes 内嵌 (个人版); 无内嵌走 exe 旁 / `%APPDATA%` mod 目录, 缺失降级纯 DSP |
| **D2** | 与 DLL 模式关系 | **独立可选开关, 不能影响 DLL 模式和主模式** | 默认关; 开启时输出端 **max 合流** (互不覆盖), 关闭态贡献恒 0 (与 v24.49 逐字节一致); 暂停/白名单语义照常尊重 |
| **D3** | 事件映射 | (原推荐"走现有事件号"被更优路线替代) | **输出端合流** 而非 VEV 事件号 —— 音频是连续电平控制不是离散事件, 且引擎/S1/S4 零改动, "不影响 DLL 模式"字面成立 |
| **D4** | 排期 | **现在就做** ("一口气全部解决") | P0+P1 一次性落地 (DSP+YAMNet+GUI+CI), 2026-11-09 完成 |
